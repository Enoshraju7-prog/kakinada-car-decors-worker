# Suggested three-minute walkthrough

1. Show the generated PDF and explain that a bill is incoming stock, not physical delivery.
2. Give the assistant a natural-language invoice goal. Expand its real tool observations: extraction, duplicate/catalogue lookup, saved draft and independent readback.
3. Show editable proposal fields, partner-owned selling price and the exact-version approval. Explain uncertainty and the bounded run budget. Do not claim a draft is posted.
4. In the seeded evaluation flow, approve the purchase, run the scoped worker again and show the saved purchase ID: 10 incoming, 0 available.
5. Record explicit synthetic physical counts, approve receipt and perform a sale. Show balances and movement history. Normal operations work without a model.
6. Give a different goal: inspect shortages, save a report and read it back. This uses the same worker and different tools.
7. Show tests for duplicate submission, concurrent final-unit sales, stale approvals and outages. State limitations plainly.

Record the screen with your own narration and upload the video to a link reviewers can open. A demo video is required by the application; this repository does not contain a recorded video. Do not give evaluators access to the real shop workspace or its credentials.
